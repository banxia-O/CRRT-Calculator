# Phase 6：最终结果页与处方摘要

Phase 6 不新增医学公式，目标是把 Phase 2–5 已经得到的输入、计算结果和校验结果整理成临床更容易核对、复制的最终输出。

## 1. 新增“结果”步骤

Stepper 末尾新增第 5 步“结果”。

最终结果页集中显示：

- 液体量
  - 目标总流出液量
  - 置换液 + 透析液
  - 置换液速度
  - 透析液速度
  - 净超滤速度
- 抗凝
  - 枸橼酸或普通肝素已计算结果
- 电解质 / 缓冲液
  - 葡萄糖酸钙
  - NaHCO₃
  - KCl
- Phase 5 临床校验结果
- 可复制文本预览

未启用的选填模块不会强行生成空处方内容。

## 2. 一键复制

新增 `src/output/prescription.ts`，把当前可见输入和已经完成的计算结果生成为纯文本摘要。

文本结构：

```text
CRRT / CBP 处方参数计算摘要

【当前输入】
...

【液体量】
...

【枸橼酸抗凝 / 普通肝素抗凝】
...

【葡萄糖酸钙】
...

【NaHCO₃（碳酸氢钠）】
...

【KCl（氯化钾）】
...

【需核对】
...

【公式库主要依据版本】
...
```

Warning / Info 会写入“需核对”部分，避免复制时丢失重要提示。

摘要同时列出当前公式库的主要依据版本，方便临床核对；更细的逐条公式来源管理放在 Phase 7 完善。

## 3. 复制安全门槛

“一键复制处方摘要”需要同时满足：

- 已填写有效体重
- 已选择治疗模式
- 已填写有效目标治疗剂量
- 液体量主流程已经得到 `ready` 结果
- Phase 5 不存在 Error 级问题

Warning 不禁止复制，但会进入摘要的“需核对”部分。

这意味着数学冲突、明显非法输入等不会被直接包装成可复制结果。

## 4. 医院离线兼容

正式交付目标仍是 `dist/index.html` 单文件，通过 U 盘带入医院内网电脑后直接双击使用。

部分医院电脑从 `file://` 打开 HTML 时可能不允许现代 Clipboard API，因此复制逻辑采用两级策略：

1. 优先 `navigator.clipboard.writeText`
2. 不可用或失败时，回退到浏览器传统本地复制方式

因此复制功能不依赖网络、后端或外部服务。

## 5. 其他交互

最终结果页支持：

- 返回修改
- 清空重算
- 一键复制处方摘要
- 复制成功 / 失败状态提示

当前不加入自动打印模板，后续如果 ICU 有固定纸质医嘱格式，可单独扩展。

## 6. 代码

- `src/output/prescription.ts`：纯文本摘要生成
- `src/output/prescription.test.ts`：摘要生成测试
- `src/App.tsx`：最终结果步骤、复制逻辑和安全门槛
- `src/styles.css`：最终结果页布局

Phase 6 不改变 Phase 2–5 的医学计算公式。
