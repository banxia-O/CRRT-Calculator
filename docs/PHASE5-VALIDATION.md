# Phase 5：临床规则与防呆校验

Phase 5 新增独立 `src/validation/` 层。它不重新计算处方，也不替医生选择治疗目标，只负责在输入和已接入公式之间做一致性检查。

## 1. 校验级别

### Error

用于数学上不成立、输入单位/符号明显错误或会导致错误换算的情况，例如：

- 体重、目标治疗剂量填写为 0 或负数
- 净超滤速度为负数
- 净超滤速度高于 `体重 × 目标治疗剂量` 得到的目标总流出液量
- CVVHDF 自定义置换液 / 透析液占比超出 0%–100%
- CVVHDF 自定义占比合计不为 100%
- 自定义制剂浓度 ≤ 0
- 目标 HCO₃⁻ 浓度低于基础液 HCO₃⁻ 浓度，却仍试图通过加入 NaHCO₃ 实现
- 目标处方液钾浓度低于基础液钾浓度，却仍试图通过加入 KCl 实现
- 单袋基础处方液体积 ≤ 0

### Warning

用于缺少计算所需字段、已知指南范围不匹配或当前版本无法自动给出明确结果的情况，例如：

- 缺少体重 / 治疗模式 / 目标治疗剂量
- CVVHDF 未选择 1:1 或自定义比例
- RCA 缺少血流量、枸橼酸制剂或补钙相关输入
- 自定义制剂未填写实际浓度
- 高钾血症情景下，目标处方液钾浓度高于 2026 版指南给出的 0–2 mmol/L 范围
- 选择“其他”但未填写具体内容

### Info

用于说明当前版本的自动化边界，例如：

- CVVH / CVVHDF 未记录前 / 后稀释方式
- “其他”治疗模式或抗凝方式仅作记录，不套用自动公式
- 0.5% 枸橼酸盐置换液不复用 4% 枸橼酸钠独立泵速公式

## 2. UI 行为

- 右侧结果栏顶部显示“临床校验”卡片。
- 错误、提醒分别显示数量。
- 具体问题按 Error / Warning / Info 分色展示。
- 与某个字段直接相关的问题会在左侧对应字段下方同步显示。
- 当前阶段不禁止用户切换步骤，避免在录入过程中被流程锁死。
- 后续 Phase 6 在“一键复制 / 最终处方摘要”时可利用 `hasErrors` 阻止把明显错误结果当作正式输出。

## 3. 医学边界

Phase 5 不新增新的治疗推荐阈值，主要复用 Phase 2–4 已核对过的规则：

- CRRT 液体量的数学关系与模式拆分
- RCA 4% 枸橼酸钠的初始换算边界
- 普通肝素输入完整性与单位检查
- RCA 补钙方案的适用条件
- NaHCO₃ / KCl 纯配液换算关系
- 2026 版 CRRT 处方液指南对高钾血症处方液钾浓度 0–2 mmol/L 的范围提示

校验层不会根据单次血气、血钾、离子钙或出血风险自动修改处方。

## 4. 代码

- `src/validation/prescription.ts`：校验规则与问题分级
- `src/validation/prescription.test.ts`：规则测试
- `src/App.tsx`：展示校验结果并把问题映射回字段

## 5. 当前测试覆盖

至少覆盖：

- 净超滤 > 目标总流出液量
- CVVHDF 自定义比例不合计 100%
- RCA 缺少血流量 / 目标枸橼酸浓度超出传统初始范围
- 目标钾低于基础液钾浓度
- 高钾血症目标处方液钾浓度 > 2 mmol/L
- 切换治疗模式后不误报已经隐藏的 CVVHDF 比例字段
- “其他”选项缺少自由文本
